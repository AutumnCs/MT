# MeituanAgent 项目介绍

## 1. 项目定位

MeituanAgent 是一个面向本地生活场景的智能路线规划系统。它的核心目标不是简单推荐几个地点，而是让用户用自然语言表达出行想法，系统自动理解需求、召回 POI、排序打分、组合路线，并支持方案切换、结果解释、继续修改和轻量个性化。

当前项目采用 Flutter 前端和 FastAPI 后端。前端提供“自然语言入口 + 结构化路线工作台”的交互体验；后端负责意图解析、POI 召回、POI 排序、路线组合、地图预览、上下文记录和响应解释。

当前支持城市为广州和上海，本地 `pois.json` 包含 125 个 POI。POI 数据包含类别、坐标、片区、价格、评分、停留时长、营业时间、室内外属性、排队等级、评论关键词、适用人群和体验分等字段。

## 2. 设计目标

### 降低输入成本

用户不需要填写复杂表单，可以直接说出需求。系统从自然语言中提取城市、起点、时间、预算、偏好、避让项、交通方式和必去点。

### 提升路线可执行性

系统不是只返回 POI 列表，而是生成多站路线。路线会考虑停留时长、转场距离、预算、类别覆盖、排队风险、片区紧凑性和顺序表达。

### 支持动态修改

用户拿到路线后可以继续说“太贵了”“不要排队”“更轻松一点”“换成室内点”等。系统基于当前路线和当前会话上下文进行增量重排。

### 保证结果可解释

路线结果包含系统理解、站点推荐理由、顺序理由、风险提示、路线诊断和地图来源。用户可以知道系统为什么选这些点、为什么这样排序、修改后发生了什么变化。

## 3. 当前功能闭环

1. 用户输入自然语言需求。
2. 后端采用 LLM-first 方式解析意图，并用本地词典和 schema 收口。
3. 如果需求过泛，系统返回一轮澄清问题。
4. 后端根据意图召回本地 POI。
5. 多因子排序计算 POI 得分和推荐理由。
6. 路线规划器生成推荐方案、偏好优先版和紧凑少走版。
7. 响应生成器输出路线摘要、站点时间线、解释、风险和 trace。
8. 前端展示路线工作台和地图预览。
9. 用户可继续修改路线。
10. 上下文服务记录会话事件、路线版本和轻量画像。

## 4. 系统架构

### 前端

- `lib/main.dart`：首页、城市选择、自然语言输入、偏好标签和路线生成入口。
- `lib/pages/route_result_page.dart`：路线工作台、方案切换、时间线、诊断信息和修改入口。
- `lib/pages/clarification_page.dart`：澄清交互。
- `lib/pages/knowledge_explanation_page.dart`：系统理解和解释逻辑。
- `lib/widgets/route_map_view.dart`：地图预览。

### 后端

- `backend/main.py`：FastAPI 入口。
- `backend/core/intent_parser.py`：本地意图解析、LLM 结果归一化、修改提示处理。
- `backend/services/route_service.py`：路线生成总编排。
- `backend/services/poi_retriever.py`：POI 召回。
- `backend/services/ranker_engine.py`：POI 多因子排序。
- `backend/services/route_planner.py`：Beam Search 路线组合和多方案生成。
- `backend/services/response_generator.py`：响应解释和 trace。
- `backend/services/context_service.py`：会话、路线版本和画像。
- `backend/services/map_service.py`：天地图封装和本地兜底。

## 5. 算法链路

### 意图解析

系统采用 LLM-first 解析，并结合本地词典规则做归一化。解析结果进入 `ParsedIntent`，字段包括城市、时间、预算、类别、偏好、避让项、节奏、交通方式、必去点和未归类线索。

### POI 召回

召回阶段根据城市、类别、偏好、软偏好、未归类线索、起点和必去点筛选候选。若候选不足，会从同城 POI 中补充高分候选，保证规划器有足够搜索空间。

### POI 排序

排序使用多因子可解释打分，包括偏好匹配、语义匹配、类别匹配、评分、预算、时间适配、排队惩罚、拥挤惩罚、价格惩罚和修改惩罚。每个 POI 都保留分项得分和推荐理由。

### 路线规划

路线规划器采用 Beam Search 与启发式补全。它优先满足必去点和必要类别，再在时间、预算、距离、片区聚合和路线得分之间做平衡。系统会生成多个策略方案，供用户切换比较。

### 响应解释

响应层把内部路线转为前端可展示结构，并生成站点选择理由、顺序理由、风险提示、路线统计和诊断 trace。

## 6. 核心创新

- 将自然语言入口和结构化路线工作台结合。
- 将 LLM 语义解析与确定性路线规划解耦。
- 使用可解释多因子排序，而不是黑盒 POI 推荐。
- 在路线层做组合搜索，而不是简单取 Top-N POI。
- 支持基于当前路线的增量修改。
- 使用轻量上下文和画像作为软偏置。
- 地图服务采用天地图优先、本地兜底的可降级设计。

## 7. 验证结果

项目包含离线评测脚本：

```powershell
cd G:\MeituanAgent\backend
python -m eval.eval_runner
```

当前评测集 `backend/eval_cases.json` 包含 25 个用例，覆盖意图解析和路线修改。本地最近运行结果为 25/25 通过。

评测脚本会设置 `LLM_INTENT_DISABLE_LLM=1`，用于验证本地规则解析和后续规划链路稳定性。

## 8. 优化展望

后续优化会沿着现有架构继续增强：

- 数据层：扩展城市、POI 数量和评论语义信号。
- 算法层：增强层次化意图、多路召回、学习排序、多目标优化和 Route Critic。
- 地图层：将真实路网、营业时间、天气和人流更深接入规划。
- 记忆层：从会话级画像扩展到更稳定的长期偏好。
- 产品层：增强路线对比、手动编辑、分享卡片和演示模式。

## 9. 总结

MeituanAgent 已形成从自然语言输入到路线生成、解释、修改、地图预览和上下文记录的完整工程闭环。项目的重点不是让大模型直接编路线，而是把大模型放在意图理解入口，后续通过可控的数据、规则、排序和规划算法生成可执行路线。
