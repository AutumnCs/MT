# 优化展望与优先级

这份文档记录当前项目在已有闭环基础上的后续优化方向。它不是旧阶段待办清单，而是面向比赛答辩和后续迭代的路线图。

## 总原则

- 保持当前“LLM 解析 + 本地可解释规划”的架构。
- 优先做能提升路线质量、解释质量和演示稳定性的优化。
- 新算法能力要能落到字段、策略、评测和 trace。
- 不为了“看起来先进”引入过重框架。

## 第一优先级：算法质量

### 目标

让路线更符合真实出行决策，而不是简单串联高分 POI。

### 方向

- 层次化意图表示。
- 多路 POI 召回。
- 可解释排序与学习排序结合。
- 带约束路线组合优化。
- 多目标 Pareto 方案生成。
- Route Critic 评审闭环。

## 第二优先级：POI 数据语义增强

### 目标

让地点数据能够支撑更细的用户需求。

### 方向

- 扩城市和 POI 数量。
- 增强评论关键词和 `review_signals`。
- 增加早茶、高端体验、亲子友好、低排队风险、雨天友好等语义标签。
- 建立 POI 数据更新和校验流程。

## 第三优先级：多轮修改体验

### 目标

让用户感觉系统是在修改当前路线，而不是每次重新生成。

### 方向

- 路线修改最小编辑。
- 修改前后 diff 展示。
- 支持锁定、删除、替换站点。
- 强化“保留前两站”“只换贵的”“最后换夜景”等局部修改。

## 第四优先级：地图与真实约束

### 目标

让路线更接近真实可执行状态。

### 方向

- 将天地图路线结果更深接入规划阶段。
- 强化营业时间和最佳访问时段。
- 引入天气、人流、排队和节假日风险。
- 优化地图 polyline、segments 和来源诊断。

## 第五优先级：评测体系

### 目标

让算法优化可量化。

### 方向

- 意图字段 F1。
- 类别覆盖率。
- 必去点命中率。
- 预算超限率。
- 转场占比。
- 路线多样性。
- 修改生效率。
- 解释一致性。

## 第六优先级：前端工作台

### 目标

让路线结果更容易理解和比较。

### 方向

- 多方案对比。
- 地图主视觉增强。
- 路线编辑入口。
- 分享卡片。
- 演示模式。
- 诊断信息更轻量可读。

## 暂不优先

- 不优先上完整重型 agent 框架。
- 不优先拆微服务。
- 不优先把所有历史对话塞进 prompt。
- 不优先做无法评测的复杂长期记忆。
- 不优先把能力注册表变成长尾口语词典。

## 一句话总结

后续优化重点是：先把路线质量、POI 语义、多轮修改和评测体系做深，再继续增强地图真实约束和前端表达。
