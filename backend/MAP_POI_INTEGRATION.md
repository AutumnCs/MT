# 本地规划 + 高德联动

这份文档说明：我们为什么先在本地做粗规划，再把结果交给高德做真实路径计算。

## 1. 分工原则

- 我们的系统负责“理解用户”和“决定去哪些点”。
- 高德负责“地理事实”和“真实路径”。
- 不把我们的语义标签直接塞进高德。
- 不让高德替我们做偏好理解。

## 2. 推荐流程

1. 用户输入需求。
2. LLM 先把需求转成结构化意图。
3. 后端根据意图筛选和打分 POI。
4. 先生成一版粗路线：点位顺序、停留时长、交通方式。
5. 把点位和坐标对齐到高德。
6. 用高德计算真实距离、真实耗时、实况转场。
7. 前端展示最终路线和地图预览。

## 3. POI 需要有哪些对接字段

建议每个 POI 都尽量有：

- `name`
- `city`
- `district`
- `address`
- `latitude`
- `longitude`
- `provider`
- `provider_poi_id`
- `adcode`
- `source_updated_at`
- `geocoded_confidence`
- `category`
- `tags`
- `price`
- `rating`
- `visit_duration`

## 4. 高德适合做什么

- 地址转坐标
- 坐标反查地址
- POI 搜索和校验
- 步行 / 打车 / 地铁的真实路线规划
- 地图可视化

## 5. 我们自己应该保留什么

- 偏好标签
- 避让项
- 节奏控制
- 是否适合拍照 / 约会 / 亲子 / 本地特色
- 多 POI 的组合策略
- 路线解释和修改建议

## 6. 一句话总结

我们先做“懂用户、会选点”的粗规划，再让高德做“真实地理和路径”的精算。
